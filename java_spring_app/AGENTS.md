# AGENTS.md - Codex運用ガイド

## 目的
- ITS (Issue Tracking System) プロジェクトで複数AIエージェントが一貫したふるまいを維持するための指針をまとめる。
- Codex (GPT-5) が作業内容・回答・生成ドキュメントを**必ず日本語で**提供することを明示する。

## プロジェクト概要
- Spring Boot 2.5系／Java 11／Gradle構成の課題管理システム。
- 詳細な技術スタックやコーディング規約は `CLAUDE.md` を参照し、それに従う。

## Codex基本ルール
1. すべてのユーザー向け回答を日本語で書く。英語混在が必要な場合も説明は日本語で補足する。
2. 追加で作成・更新するドキュメント (README, 設計メモ, コメント等) も日本語で記述する。
3. 作業開始前に `AI_INSTRUCTIONS.md` と `CLAUDE.md` を読み、最新の制約や優先順位を確認する。
4. 破壊的コマンド (`git reset --hard`, `rm -rf` など) はユーザーが明示しない限り実行しない。
5. 既存の手動変更を尊重し、意図が不明な差分を勝手に消さない。

## 作業フロー推奨ステップ
1. `git status -sb` で作業ツリーを確認し、他者の変更を把握する。
2. 要求の範囲を整理し、必要であれば `CLAUDE.md` の規約と突き合わせてタスクリストを作成する。
3. 実装・修正後は関連箇所のビルド／テスト (`./gradlew test` など) を日本語コメント付きで記録する。
4. 変更内容を日本語でまとめ、影響範囲と次のアクション案を提示する。

## ドキュメントとコミュニケーション
- コードコメントも含め、利用者が読む情報は原則日本語で残す。
- コマンド例やコードブロック内の識別子は原文でもよいが、前後に日本語の説明を添える。
- レビュー観点・テスト結果・既知のリスクは箇条書きで明瞭に記述する。

## 禁止事項
- セキュリティ情報 (APIキー・パスワード) のハードコード。
- ライセンス不明の外部コード貼り付け。
- 指定外ディレクトリでのファイル削除や生成。

## 参考リソース
- `AI_INSTRUCTIONS.md`: 全体方針や作業上の注意点。
- `CLAUDE.md`: 技術スタック、コーディング規約、セキュリティ要件。
- 本 `AGENTS.md`: Codex の言語運用とワークフローまとめ。
