#### Claude Code おすすめ（勉強会向け）

勉強会では「迷ったら一番シンプルな方を選ぶ」のが原則。実装の難易度を下げることで、全員が完成まで到達しやすくなる。

| 課題 | おすすめ | 理由 |
|------|----------|------|
| 公開範囲の非会員可否 | **全て会員のみ（ログイン必須）** | 非会員閲覧を入れると認可ロジックが複雑になる。ログイン必須なら「認証済みかどうか」だけで判定できる |
| 画像機能 | **MVPでは含めない（テキストのみ）** | ファイルアップロードは初心者には難易度が高い。後から追加できる |
| 共同管理者 | **なし（1人オーナー）** | 権限管理が複雑になるので、MVPでは不要 |
| フォローの承認制 | **なし（片方向フォローのみ）** | 承認フローは画面・通知が増える。フォローボタン1つで済む方が簡単 |

#### Claude Code おすすめ（勉強会向け）

| 課題 | おすすめ | 理由 |
|------|----------|------|
| SSR / SPA | **SSR（Thymeleaf）** | Spring Boot単体で完結。フロント別プロジェクトが不要で、環境構築がシンプル |
| DB | **H2（開発環境）** | セットアップ不要。`bootRun` だけで動く。全員の環境差が出にくい |
| 画像保存先 | **MVPでは実装しない** | テキストのみで開始し、余力があれば追加 |
| デプロイ | **ローカルのみ** | 各自のPCで動けばOK |
| 認証方式 | **Spring Security セッション方式** | Spring Boot標準で設定例も多く、学習しやすい |
