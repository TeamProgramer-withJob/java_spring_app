# AGENTS.md - Codex運用ガイド

## 目的
- 結びの霊園プロジェクトで複数AIエージェントが一貫したふるまいを維持するための指針をまとめる。
- Codex / Claude Code が作業内容・回答・生成ドキュメントを**必ず日本語で**提供することを明示する。

## プロジェクト概要
- Spring Boot 3.2.1／Java 21／Gradle 8.5 構成のオンライン霊園Webアプリケーション。
- DB は SQLite（開発環境）、画像は DB BLOB 保存、認証は Spring Security セッション方式。
- 詳細な技術スタックやコーディング規約は `CLAUDE.md` を参照し、それに従う。

## Codex基本ルール
1. すべてのユーザー向け回答を日本語で書く。英語混在が必要な場合も説明は日本語で補足する。
2. 追加で作成・更新するドキュメント (README, 設計メモ, コメント等) も日本語で記述する。
3. 作業開始前に `AI_INSTRUCTIONS.md` と `CLAUDE.md` を読み、最新の制約や優先順位を確認する。
4. 破壊的コマンド (`git reset --hard`, `rm -rf` など) はユーザーが明示しない限り実行しない。
5. 既存の手動変更を尊重し、意図が不明な差分を勝手に消さない。

## 指揮命令系統（最重要）
- **Codex はAIチームリーダー**として、要件整理、タスク分解、優先順位付け、レビュー、最終承認を担当する。
- **Claude Code は実装担当**として、Codex の依頼文に基づく実装・テスト・報告を担当する。
- Claude Code は、Codex の承認なく設計方針・タスク範囲を拡張しない。
- 仕様曖昧点・トレードオフ・影響範囲拡大の判断は Codex が最終決定する。
- **マージ/リリース可否は Codex の `OK` 判定後のみ**とする。

## AI役割分担ルール
- **Claude Code（実装担当）**
  - 実装作業、ドキュメント更新、定型的なテスト追加を担当する。
  - 指示されたタスク単位で変更を実施し、変更ファイルとテスト結果を日本語で報告する。
- **Codex（設計・レビュー担当）**
  - タスク分解、優先順位判断、Claude Code への依頼文作成を担当する。
  - Claude Code の成果物をレビューし、`OK / 差し戻し` を判定する。
  - 仕様解釈やトレードオフがある場合の最終判断材料を提示する。

## 共同作業フロー
1. Codex が「1タスク = 1依頼文」で作業指示を作成する。
2. Claude Code が依頼文に沿って実装・修正する。
3. Codex が差分レビューを行い、必要に応じて差し戻す。
4. レビュー通過後にコミット・プッシュ・関連ドキュメント更新を行う。

## ルール優先順位
1. `AGENTS.md`（本ファイル）
2. `AI_INSTRUCTIONS.md`（日次運用ルール）
3. `CLAUDE.md`（技術規約・実装詳細）
4. 各タスク依頼文（Task単位の追加制約）

## 品質ゲート
- 必須: 変更対象に応じたビルド／テスト（例: `./gradlew test`）を実行し、結果を記録する。
- 必須: `docs/ACTION_ITEMS_v0.1.md`・`README.md`・`docs` 配下の関連文書を最新状態に保つ。
- 必須: 変更内容、影響範囲、既知リスクを日本語で明記する。
- 推奨: 小さな差分（短時間でレビュー可能な粒度）で進める。

## 作業フロー推奨ステップ
1. `git status -sb` で作業ツリーを確認し、他者の変更を把握する。
2. 要求の範囲を整理し、必要であれば `CLAUDE.md` の規約と突き合わせてタスクリストを作成する。
3. 実装・修正後は関連箇所のビルド／テスト (`./gradlew test` など) を日本語コメント付きで記録する。
4. 変更内容を日本語でまとめ、影響範囲と次のアクション案を提示する。

## ドキュメントとコミュニケーション
- コードコメントも含め、利用者が読む情報は原則日本語で残す。
- コマンド例やコードブロック内の識別子は原文でもよいが、前後に日本語の説明を添える。
- レビュー観点・テスト結果・既知のリスクは箇条書きで明瞭に記述する。

## 禁止事項
- セキュリティ情報 (APIキー・パスワード) のハードコード。
- ライセンス不明の外部コード貼り付け。
- 指定外ディレクトリでのファイル削除や生成。
