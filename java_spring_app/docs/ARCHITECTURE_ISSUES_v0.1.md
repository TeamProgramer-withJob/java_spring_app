# 結びの霊園 アーキテクチャ課題整理 v0.1

## 目的

本ドキュメントは、アーキテクチャおよび実装方針に関する未決定事項・検討事項を整理し、チームで合意形成するための課題一覧である。

---

## 1. 画面構成方式

### 課題

SSR（Thymeleaf）か SPA（React 等）かを決定する。

### 選択肢

| 方式 | メリット | デメリット |
|------|----------|------------|
| **SSR（Thymeleaf）** | Spring Boot 単体で完結、学習コスト低 | UIの自由度はやや低い |
| **SPA（React 等）** | 役割分担しやすい、拡張性高 | 構成が複雑、工数増 |

### 仮方針

SSR（Thymeleaf）を第一候補とする。

### 決定担当

未定

---

## 2. 認証・認可方式

### 課題

ログイン方式および公開範囲制御のルールを確定する。

### 検討内容

**認証方式**

- セッションログイン（Spring Security 標準）
- JWT（将来拡張向け）

**認可ルール**

- 作成者のみ編集可能
- 公開範囲判定（PUBLIC / FOLLOWER / MUTUAL / PRIVATE）

### 仮方針

Spring Security セッション方式

---

## 3. データベース方針

### 課題

利用DBおよびマイグレーション方式を決める。

### 選択肢

- PostgreSQL
- MySQL
- H2（開発用）

### 推奨

- **開発**：H2 または Docker PostgreSQL
- **本番**：PostgreSQL

### マイグレーション

Flyway を利用

---

## 4. 画像ファイルの扱い

### 課題

MVPに画像投稿を含めるか。

### 選択肢

- MVPでは含めない（テキストのみ）
- ローカル保存
- S3等の外部ストレージ

### 仮方針

MVPではローカル保存または未実装

---

## 5. デプロイ方針

### 課題

公開環境を用意するか。

### 選択肢

- ローカルのみ
- Render / Railway / Heroku 等
- AWS EC2 / ECS

### 仮方針

ローカル中心、余力があればPaaS

---

## 6. ログ・エラー処理

### 課題

例外処理とログの統一方針。

### 方針案

- `@ControllerAdvice` による共通例外処理
- 画面エラー表示の統一
- INFO/ERROR ログ出力

---

## 7. テスト方針

### 課題

何を最優先でテストするか。

### 優先度高

- 公開範囲判定
- 権限チェック
- ログイン/認証

### 優先度中

- 画面遷移
- バリデーション
