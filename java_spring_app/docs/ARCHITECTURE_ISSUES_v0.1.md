# 結びの霊園 アーキテクチャ課題整理 v0.1

> **最終更新**: 2026-02-22

## 目的

本ドキュメントは、アーキテクチャおよび実装方針に関する未決定事項・検討事項を整理し、チームで合意形成するための課題一覧である。

---

## 1. 画面構成方式

### 課題

SSR（Thymeleaf）か SPA（React 等）かを決定する。

### 選択肢

| 方式 | メリット | デメリット |
|------|----------|------------|
| **SSR（Thymeleaf）** | Spring Boot 単体で完結、学習コスト低 | UIの自由度はやや低い |
| **SPA（React 等）** | 役割分担しやすい、拡張性高 | 構成が複雑、工数増 |

### ✅ 決定（2026-02-22）

**SSR（Thymeleaf）** で実装済み。

---

## 2. 認証・認可方式

### 課題

ログイン方式および公開範囲制御のルールを確定する。

### 検討内容

**認証方式**

- セッションログイン（Spring Security 標準）
- JWT（将来拡張向け）

**認可ルール**

- 作成者のみ編集可能
- 公開範囲判定（PUBLIC / FOLLOWER / MUTUAL / PRIVATE）

### ✅ 決定（2026-02-22）

**Spring Security セッション方式** で実装済み。全画面ログイン必須。公開範囲は現状 PUBLIC 固定（フォロー機能は未実装のため）。

---

## 3. データベース方針

### 課題

利用DBおよびマイグレーション方式を決める。

### 選択肢

- PostgreSQL
- MySQL
- H2（開発用）
- SQLite（開発用）

### ✅ 決定（2026-02-22）

**SQLite**（`./data/cemetery.db`）で実装済み。schema.sql / data.sql による初期化。
マイグレーションツールは現状未導入（手動 SQL 管理）。将来 Flyway 導入を検討。

---

## 4. 画像ファイルの扱い

### 課題

MVPに画像投稿を含めるか。

### 選択肢

- MVPでは含めない（テキストのみ）
- DBにBLOBとして保存
- ローカル保存
- S3等の外部ストレージ

### ✅ 決定（2026-02-22）

**DBにBLOBとして保存** する方式で実装済み。
JPG・PNG・GIF、最大 10MB。`/cemeteries/{id}/memories/{id}/image` エンドポイントで配信。

---

## 5. デプロイ方針

### 課題

公開環境を用意するか。

### 選択肢

- ローカルのみ
- Render / Railway / Heroku 等
- AWS EC2 / ECS

### ✅ 決定（2026-02-22）

**ローカルのみ**。`./gradlew bootRun` で各自の PC 上で動作確認。
